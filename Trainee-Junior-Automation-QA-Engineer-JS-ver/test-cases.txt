=====================================================================
TEST CASES – https://automationintesting.online/
Part 1: Manual testing & documentation (UI flow: room booking)
Automated in: cypress/e2e/user-spec.cy.js  (UI)
              cypress/e2e/admin-spec.cy.js (API)
=====================================================================

Preconditions (all UI cases):
  - Browser opened, User App is available (no login needed).
  - At least one room exists (in automation it is created via Admin API).
  - Open the room's reservation page ("Book this room" on the home page).

---------------------------------------------------------------------
TC-UI-01  Room can be booked with valid data                 [Positive]
---------------------------------------------------------------------
Steps:
  1. On the calendar go to the next month.
  2. Drag-select a range of free days (e.g. 3 days in the 2nd week).
  3. Click "Reserve Now" – booking form is displayed.
  4. Fill in: Firstname = John, Lastname = Tester,
     Email = john.tester@example.com, Phone = 01234567890.
  5. Click "Reserve Now".
Expected:
  - POST /api/booking returns 201.
  - "Booking Confirmed" message with the selected dates is displayed.

---------------------------------------------------------------------
TC-UI-02  Booking with all fields empty                      [Negative]
---------------------------------------------------------------------
Steps: select dates -> "Reserve Now" -> leave all fields empty -> "Reserve Now".
Expected: booking is NOT created (400), red error list is shown
          (e.g. "must not be empty", "size must be between ..."),
          "Booking Confirmed" is not shown.

---------------------------------------------------------------------
TC-UI-03  Firstname shorter than allowed minimum (2 chars)   [Negative]
---------------------------------------------------------------------
Data: Firstname = Jo, other fields valid.
Expected: 400, validation error for Firstname, no confirmation.

---------------------------------------------------------------------
TC-UI-04  Invalid e-mail format                              [Negative]
---------------------------------------------------------------------
Data: Email = not-an-email, other fields valid.
Expected: 400, validation error "must be a well-formed email address",
          no confirmation.

---------------------------------------------------------------------
TC-UI-05  Phone number too short                             [Negative]
---------------------------------------------------------------------
Data: Phone = 123, other fields valid.
Expected: 400, validation error for Phone (length 11-21), no confirmation.

---------------------------------------------------------------------
TC-UI-06  Lastname empty                                     [Negative]
---------------------------------------------------------------------
Data: Lastname = "", other fields valid.
Expected: 400, validation error for Lastname, no confirmation.

---------------------------------------------------------------------
TC-UI-07  Booking without selecting dates                    [Negative]
---------------------------------------------------------------------
Steps: do NOT select dates -> "Reserve Now" -> fill valid data -> "Reserve Now".
Expected: booking is not created, "Booking Confirmed" is not shown.

---------------------------------------------------------------------
TC-UI-08  Earlier booked dates are shown as "Unavailable"    [Positive]
---------------------------------------------------------------------
Precondition: a booking exists for the room (e.g. 20–22 of next month).
Steps:
  1. Open the reservation page of that room.
  2. Go to the month with the booking.
Expected: booked days are displayed on the calendar as "Unavailable".

API TEST CASES
=====================================================================

TC-API-01  Create room (Admin API) -> verify in User API
  Steps : POST /api/auth/login (admin/password); POST /api/room;
          GET /api/room (no auth).
  Expected: 201 on create; the new room is in the list with the same
          name, type, accessible flag and price.

TC-API-02  Book room (User API) -> verify in Admin API
  Steps : POST /api/booking (no auth); login as admin;
          GET /api/booking?roomid={id}.
  Expected: 201 on booking; admin sees exactly this booking with the same
          names and checkin/checkout dates; GET /api/booking/summary
          shows the dates as taken.

TC-API-03  Edit room (Admin API) -> verify in User API
  Steps : PUT /api/room/{id} (type, price, description, accessible,
          features changed); GET /api/room (no auth).
  Expected: 202 on update; user sees all updated values.

TC-API-04  Delete room (Admin API) -> verify in User API
  Steps : DELETE /api/room/{id}; GET /api/room (no auth).
  Expected: 200/202/204 on delete; the room id is absent in the list.

TC-API-05  Create room without authorisation                 [Negative]
  Expected: 401.

TC-API-06  Book room with invalid data via API               [Negative]
  Data  : email = "invalid", firstname = "Jo".
  Expected: 400.

TC-API-07  Home page loads rooms from GET /api/room (cy.intercept)
  Expected: request status 200, body.rooms is a non-empty array.
